# QA Report: BeatDrop, 2026-11-14
URL: https://beatdrop-self.vercel.app (production, commit 7f2c5dd)
Method: the playwright-qa agent read the source code only, because it had no browser tools and its rules forbid testing production. The main bug (BUG-001) was then reproduced in the Claude built-in browser on production (desktop viewport, cookies set to essential-only, nothing submitted).

## Summary
Critical: 1 (reproduced) | High: 1 | Medium: 1 | Low: 1

## Bugs

### BUG-001 [Critical] Switching language TH→EN crashes with "Application error: a client-side exception" (reproduced)
- URL: /play → /en/play (expected on every page and in both directions)
- Steps:
  1. Open https://beatdrop-self.vercel.app/play and wait about 8 seconds (until the boot splash is gone from the DOM).
  2. Choose "ใช้เฉพาะที่จำเป็น" in the cookie banner.
  3. Open "ตั้งค่าและธีม" and click English.
- Expected: navigates to /en/play with the UI in English.
- Actual: the URL changes to /en/play, but the page shows only "Application error: a client-side exception has occurred…", the same as the user's iPhone screenshot.
- Console (actually captured):
  ```
  Uncaught NotFoundError: Failed to execute 'removeChild' on 'Node': The node to be removed is not a child of this node.
      at ud (.../_next/static/chunks/4bd1b696-f785427dddbba9fb.js:1:96627)
      at uf (...:1:96077) ...
  ```
- Root cause:
  - `components/AppShell.tsx` (the splash effect) calls `splash.remove()` on `#beatdrop-boot-splash`, but React rendered that element in `app/[locale]/layout.tsx`.
  - When the `[locale]` segment changes, React unmounts the old layout and calls removeChild on a node that is already gone, so it throws.
  - The bug started with commit 7f2c5dd / 332ef95 (the boot splash).
- Fix direction: React must own the splash's lifecycle. Use only `data-hidden` / `display:none`, and do not remove the node by hand.

### BUG-002 [High] The boot splash comes back on every language switch (from code reading, not confirmed in a browser)
- The new LocaleLayout renders the splash again, and AppShell remounts with `splashDone=false`, so the full-screen splash covers the page for 0.25–6 s.
- GameProvider and ConsentProvider remount too, so a round in progress may be lost.
- Files: `app/[locale]/layout.tsx`, `components/AppShell.tsx`

### BUG-003 [Medium] There is no `error.tsx` / `global-error.tsx`
- Any client error turns into Next's default English full-screen "Application error" with no retry button.

### BUG-004 [Low] Fixed text that does not follow the locale
- `components/AppShell.tsx`: "HEAR LESS. KNOW MORE." is hardcoded (possibly intentional branding).
- `app/not-found.tsx`: always `lang="th"` and mixes TH/EN text.

## What passed
- /play loads on production, the cookie banner works, and the settings menu shows the language choice.
- The language switcher keeps the path and query string (from code reading).
- The messages for th and en have the same 23 namespaces (file count only).
